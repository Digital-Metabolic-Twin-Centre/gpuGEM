## SolveResult / ModelComparison / ViolationHistogram (unchanged shape, new rows)

No schema changes anywhere. This feature populates already-existing shapes for one more model:

- `benchmarks/results/Harvetta.json` — the 002-style cross-scale `SolveResult` (cuOpt shipped
  default + Gurobi, correctness-gated).
- `benchmarks/results/residual_tradeoff/Harvetta.json` — the 005/007-style `ModelComparison`
  (`shipped_default` reused from the file above, `residual_0` solved fresh with both
  `violation_histogram_equations` and `violation_histogram_constraints` populated since Harvetta
  has a genuine coupling block, `gurobi` reused).
- `benchmarks/results/benchmark.csv` and `benchmarks/results/residual_tradeoff/comparison.csv` —
  both grow by one model's rows (10 and 30 total respectively, up from 9 and 27).

## TrackedModelFile (new concept — a version-control state, not application data)

Not a runtime data structure; describes which files in `benchmarks/model_cache/` are committed
after this feature (research R3):

| File | Tracked after this feature? |
|---|---|
| `e_coli_core.xml`, `iML1515.xml` | Yes (already tracked today — unaffected). |
| `Harvetta_1_03d.mat` | Yes (new). |
| `mWBM_{S9,S15,S23,S83}_male.mat` | Yes (new — the plain variants `REGISTRY` already references). |
| `mWBM_{S9,S15,S23,S83}_male_lifted.mat` | No — remains excluded via a narrowed `.gitignore` pattern (`benchmarks/model_cache/*_lifted.mat`); not referenced by any `REGISTRY` entry or published result. |

Invariant this feature establishes going forward: every file `REGISTRY` references is tracked;
files present in `model_cache/` but not referenced by any `REGISTRY` entry (e.g. a future `_lifted`
addition) stay untracked by default until a future feature deliberately registers and commits them.
